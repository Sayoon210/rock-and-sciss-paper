# 2026-08-16 — Core 경계에 대한 오해 정정

[프로젝트 구조 결정](2026-08-16-project-structure.md) 이후, 실제로 세팅해둔 구조를 다시 짚어보면서 오해 두 가지를 바로잡은 기록. 새 결정은 없고, 기존 결정의 **의미를 잘못 이해할 뻔한 지점**들을 정정함.

## 확인 1: Core는 평범한 .NET 클래스 라이브러리

- `Core/RockAndScissPaper.Core.csproj`는 `Microsoft.NET.Sdk`(웹 API, 콘솔 앱 등에도 쓰는 그 기본 SDK)를 씀. `Godot.NET.Sdk`가 아님.
- `Main()`이 없음 — 실행 파일이 아니라 라이브러리(`.dll`). 혼자 못 돌고 참조하는 쪽(Godot 프로젝트, Tests)이 있어야 의미가 생김.
- GodotSharp을 참조하지 않으므로 Godot이 설치 안 된 환경에서도 `dotnet build`/`dotnet test`가 그대로 됨. 실제로 지금까지 `WinLossRules` 검증을 전부 Godot 에디터 없이 CLI로만 했음.

## 정정 1: "테스트용으로 조금 뽑아낸 것" → 실제로는 게임 규칙 대부분이 여기로 감

- 처음 든 생각: 다른 로직들은 다 Godot 쪽에서 돌고, Core는 테스트 편의를 위해 일부만 뽑아둔 것 아닌가.
- 정정: 기준은 "테스트하기 좋아서"가 아니라 **"Godot이 진짜로 필요한가"**. [Scripts/Autoload/CLAUDE.md](../Scripts/Autoload/CLAUDE.md)에 이미 적힌 원칙(*Autoload은 얇게, 실제 규칙은 Core의 순수 클래스에*)대로면, 라운드 판정·카드 효과·덱/패 조작·스코어 같은 실질적 규칙은 거의 다 Core로 가고, Godot 쪽엔 RPC 송수신·씬/노드·UI 같은 "Godot이 아니면 원래 못 하는 것"만 남음.
- **Why 정정이 필요했나**: 이 오해대로 진행하면 나중에 새 로직 짤 때 "일단 Godot 쪽에 짜고 나중에 필요하면 뽑자"는 방향으로 가기 쉬운데, 실제 원칙은 반대(기본값이 Core, Godot은 예외)라 처음부터 뒤집어서 짜게 됨.

## 확인 2: 컴파일 타임 경계 ≠ 런타임 비용

- 빌드 시 Core.dll이 먼저 만들어지고, Godot 프로젝트가 `<ProjectReference>`로 참조해서 최종 빌드에 같이 포함됨.
- 실행 시엔 **한 프로세스 안에 두 어셈블리가 같이 로드됨** — 별도 프로그램도, 프로세스 간 통신도 아님. `GameState`(Godot)가 `WinLossRules.Judge(...)`(Core)를 부르는 건 같은 프로젝트 안 다른 파일의 메서드를 부르는 것과 동일한 비용.
- 정리: 경계는 **"누가 누굴 참조할 수 있냐"만** 컴파일 타임에 막고, 런타임엔 그 벽이 사라져서 한 몸으로 동작함.

## 정정 2: "Core = 호스트 전용 실행"이 아님

- 처음 든 생각: 멀티플레이어에서 호스트만 로직을 돌리고 싶어서 그걸 Core에 몰아둔 것 아닌가.
- 정정: **Core.dll은 호스트와 클라이언트 양쪽에 동일하게 존재함.** 빌드 시 실행 파일에 통째로 링크되므로, 클라이언트 컴퓨터에도 `RoundResolver` 등 Core 코드가 그대로 들어있음. Core는 자신이 호스트에서 도는지 클라에서 도는지 알 방법도 관심도 없음 (Player1/Player2만 알고 peer ID나 host 여부는 아예 모르는 설계 — [Core/CLAUDE.md](../Core/CLAUDE.md) 참고).
- **실제 호스트 전용 실행은 런타임 분기로 만들어짐**: `GameState._session`이 호스트에선 실제 세션 객체, 클라에선 항상 `null`. 클라의 `GameState`는 `_session`이 없어서 애초에 `RoundResolver`를 부를 게 없음 — 코드가 없어서가 아니라 부르지 않도록 짜여서 안 도는 것.
- Core 분리(컴파일 타임 경계)와 호스트 권위(런타임 분기)는 **서로 다른 문제를 푸는 별개의 메커니즘**이고, 하나가 다른 하나의 이유가 아님:

| | Core/Godot 분리 | 호스트 권위 |
|---|---|---|
| 막는 것 | Core가 Godot 타입 쓰는 것 | 클라가 규칙을 직접 실행하는 것 |
| 시점 | 컴파일 타임 (참조 없음 → 빌드 실패) | 런타임 (null 체크) |
| 이유 | 테스트를 빠르게 하려고 | 치팅 방지 / 정보 비대칭 유지 |
| Core 코드가 클라에 있나 | — | 있음. 그냥 안 불릴 뿐 |
