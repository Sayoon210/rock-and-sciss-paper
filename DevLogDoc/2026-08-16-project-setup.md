## 기술 스택 결정 (CLAUDE.md)

- 스크립팅 언어: C# 단독, GDScript 안 씀. **Why**: 포트폴리오로도 쓸 예정이라 코드 가독성/구조가 더 잘 드러남.
- 멀티플레이어: Godot 내장 고수준 API(`ENetMultiplayerPeer` + RPC) 사용, GDExtension/C++ 네트코드는 안 씀. **Why**: 턴제 카드게임은 실시간 프레임 동기화가 필요 없어서 커스텀 네트코드는 과함.

- 호스트 권위 구조 + 정보 비대칭(숨김 정보는 타겟 RPC로만 전송), `MultiplayerSynchronizer` 전체 동기화 지양. **Why**: 카드게임은 상대 패를 숨겨야 하는데 기본 동기화 패턴은 이걸 다 노출시킴.
- Autoload는 "단일 목적" 원칙만 지키고 이름 목록은 고정하지 않음. **Why**: 나중에 하나 추가할 때마다 "허용 목록"처럼 문서를 계속 고쳐야 하는 걸 피함.
- CLAUDE.md 포맷: 섹션마다 Rules/Avoid를 나누던 걸 최상단 통합 Rules/Avoid + 설명형 섹션으로 바꾸고, 이후 전체를 리스트 포맷으로 통일. **Why**: 섹션별 반복 구조가 가독성을 해치고, 줄글은 중간 내용이 묻힘.

## 게임 기획 (DESIGN.md)

- 장르: 가위바위보 상성 기반 TCG, 1:1, **5선승제**로 확정(10선승에서 축소). **Why**: 무승부/특수카드 라운드가 스코어에 안 들어가서 라운드 수가 유동적으로 늘어남 — 고정 판수보다 "레이스" 형식이 맞음.
- 덱 **20장** = 가위/바위/보 각 3장(9) + 더미 4 + 조커 1 + 특수 6, 여러 차례 매수 조정(15→21장 사이를 오감) 끝에 확정.
- 멀리건: 특정 구성을 보장하던 룰을 버리고 "셔플 후 덱탑 6장" 완전 랜덤으로 단순화. **Why**: 특정 카드 조합을 보장하는 복잡한 룰보다 구현/이해가 쉬움.
- 특수카드는 전부 "사용 후 소멸"로 통일(더미카드만 예외였던 걸 없앰). **Why**: 예외 케이스를 줄여 규칙을 단순화.
- **조커카드** 도입: 최우선 처리, 상대 카드 소멸 + 효과 자체 차단, 사용 후 자신도 소멸, 조커끼리는 서로 소멸만. **Why**: 상대 특수카드 효과를 무효화할 수단이 필요했음.
- **더미카드** 도입: 효과 없이 소멸, 내 카드 소모 없이 상대가 이번 라운드에 뭘 냈는지 확인(정찰)하는 용도.
- 라운드 처리 통일: 모든 라운드가 예외 없이 "카드는 덱 바닥 복귀 또는 소멸 + 양쪽 드로우 1장"으로 처리됨 (기존 "무승부면 패로 복귀, 드로우 없음" 규칙 폐기). **Why**: 특수 케이스를 줄여 구현/이해를 단순화.
- 특수카드 6종 확정: 리셋(유일하게 상대에게도 영향), 교체, 변화(일반↔더미 상호 변환), 보충(더미 추가), 예지(top3 확인 후 1장을 다음 드로우로 지정), 드로우(2장).
- 카드 처리 우선순위 도입: 조커 > 리셋 > 그 외 특수 > 나머지, 동순위는 Player1 카드부터. **Why**: 양쪽이 동시에 특수계열 카드를 냈을 때 처리 순서가 결과에 영향을 주므로 결정적 규칙이 필요했음.
- 특수카드는 현재 6종이 전부지만, 나중에 풀을 늘려 선택하는 덱빌딩으로 확장 가능하게 설계 여지를 남김(`CardDatabase`에서 읽어오게, 하드코딩 금지). **Why**: 지금 당장 구현하진 않아도 나중에 막히지 않게.
