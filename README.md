# RockAndScissPaper 3D

가위바위보를 카드 게임으로 확장한 1:1 실시간 멀티플레이어. Godot 4.7 (Mono / C#).

테이블을 사이에 두고 마주 앉아 카드를 낸다. 이긴 쪽은 진 쪽을 실제로 때리고, 무엇으로
이겼는지에 따라 연출과 피해량이 갈린다 — 바위는 주먹, 가위는 손을 찌르고, 보는 책상을
내려친다.

---

## 구조 — 컴파일러가 지키는 경계

```
RockAndScissPaper.csproj   Godot.NET.Sdk        씬 · 노드 · 입력 · RPC · UI
        │
        └── references ──▶ GameLogic/           Microsoft.NET.Sdk   순수 규칙, 참조 없음
                                ▲
Tests/  xUnit ──────────────────┘               GameLogic만 참조
```

**참조가 한 방향뿐인 것이 이 프로젝트의 핵심이다.** `GameLogic`은 아무것도 참조하지 않으므로
`using Godot;`이 `error CS0246`으로 **컴파일 실패한다** — 규율이 아니라 빌드가 막는다.

그 결과 두 가지를 얻었다:

- **테스트 146개가 Godot 없이 0.1초에 돈다.** 라운드 판정처럼 분기가 많고 틀리기 쉬운 코드를,
  두 인스턴스를 띄워 클릭하는 대신 함수 호출로 검증한다.
- **표현 계층을 통째로 갈아끼울 수 있다.** 2026-08-28에 2D UI 3,776줄을 들어내고 3D로 다시
  썼는데, `GameLogic`과 `Tests`는 **한 줄도 고치지 않았다.** 그 과정은
  [DevLogDoc/2026-09-06](DevLogDoc/2026-09-06-2d-to-3d-retrospective.md)에 정리해 두었다.

## 멀티플레이 — 호스트 권위

`ENetMultiplayerPeer` + Godot 하이레벨 멀티플레이어 API. 규칙은 호스트에서만 실행된다.

- 클라이언트는 "이 카드를 내고 싶다"는 **요청**만 보내고, 호스트가 검증한 뒤 결과를 뿌린다.
- 호스트는 클라이언트를 신뢰하지 않는다 — 손패에 없는 카드, 이미 제출한 뒤의 재제출 같은
  요청은 `MatchSession`이 예외를 던지고 호스트가 그걸 잡아 거부한다.
- 히든 정보는 대상 지정 RPC로만 나간다. 상대의 손패는 **개수만** 공개된다.
- 화면을 그리는 쪽은 자신이 호스트인지 클라이언트인지 알 필요가 없다. 양쪽 모두 같은 진입점
  (`GameState.RequestCardPlay`)으로 요청하고, 같은 시그널(`RoundResolved`)로 결과를 받는다.

## 규칙 요약

- 양쪽 체력 10에서 시작, 먼저 0이 되는 쪽이 패배
- 승리 수단마다 피해량이 다르다 — 바위 2, 가위 1, 보 1
- 손패 5장. 다 쓰면 한 번에 다시 채워진다 (덱이 스스로 보충)

전체 기획은 [DESIGN.md](DESIGN.md).

## 지금 되는 것 / 안 되는 것

**된다** — 접속, 3D 매치 진행, 카드 제출과 공개, 승패 판정, 체력 감소, 승리 연출(바위/가위/보
3종), 마우스 시선 추적과 그 동기화, 라운드 타임아웃.

**아직 안 된다** — 가위 승리의 부가효과(다음 턴 아이템 봉쇄)와 보 승리의 부가효과(상대 패 공개)는
기획에만 있고 구현되지 않았다. 아이템 시스템 자체가 없기 때문이다. 능력카드 4종(리셋/교체/변화/
드로우)은 코드와 테스트가 살아 있지만 현재 덱에서는 빠져 있다 — 덱은 가위/바위/보 3장씩이다.

## 실행

Godot 4.7 (**.NET / Mono 빌드**)과 .NET 8 SDK가 필요하다.

```bash
dotnet build
```

```bash
dotnet test
```

에디터에서 열려면 `project.godot`을 Godot 4.7 Mono로 열면 된다. 멀티플레이는 인스턴스 두 개를
띄워 한쪽에서 호스트, 다른 쪽에서 접속한다.
