# TypeGraph — 타입 참조 추출기

프로젝트의 모든 타입 선언과 "누가 누구를 참조하는가"를 소스에서 뽑아 `graph.json`으로
쓴다. 어디서 실행하든 저장소 루트를 기준으로 동작한다.

```bash
python Tools/TypeGraph/extract_type_graph.py
```

`Scripts/**/*.cs`와 `GameLogic/**/*.cs`를 읽고 `obj/`, `Deprecated/`는 건너뛴다.
결과는 [ARCHITECTURE.md](../../ARCHITECTURE.md)의 참조 그래프 절을 갱신할 때 쓴다.

## 왜 컴파일러 대신 정규식인가

Roslyn을 붙이면 참조는 더 정확하게 나오지만, **이 프로젝트에서 실제로 문제가 되는 결합은
컴파일러가 볼 수 없는 것들이다** — `.tscn`의 `ext_resource`, `GetNode<T>("Table/MyScissors")`
같은 문자열 노드 경로, `Tr("MATCH_LOG_HINT")`와 CSV 키의 대응. 전부 문자열이라 타입 시스템에
안 잡힌다. 그 방향으로 키울 거면 출발점이 텍스트 쪽인 편이 낫다.

## 판별한 것 두 가지

**타입 본문을 중괄호로 짝지어 잘라낸다.** 파일 단위로 참조를 모으면, 클래스 옆에 선언된
enum이 그 클래스의 참조를 통째로 물려받는다. `ESide`가 `MatchSession`의 참조 13개를 가진
것처럼 보이는 식이다.

**문자열을 주석보다 먼저 지운다.** 순서를 반대로 하면 `"res://Scenes/..."` 안의 `//`가 주석
시작으로 읽혀 닫는 따옴표까지 먹고, 그 뒤 모든 따옴표가 한 칸씩 밀린다. 중괄호가 삼켜지면서
클래스 본문이 잘리고, `MatchWorldView`의 참조가 12개가 아니라 2개로 나왔다. Godot 프로젝트는
`res://` 경로가 흔해서 이게 흔한 함정이다.

## 한계

- 정규식이다. 제네릭 인자, 별칭(`using X = Y;`), 부분 클래스의 분할 선언을 이해하지 못한다
- "참조"는 "그 타입의 본문에 이 이름이 등장한다"는 뜻이다. 주석과 문자열은 이미 지운 뒤라
  거짓 양성은 적지만, 지역 변수 이름이 타입명과 같으면 걸린다
- `graph.json`은 생성물이다. 커밋해 두는 이유는 스크립트를 안 돌려도 diff에서 구조 변화가
  보이게 하기 위해서다
